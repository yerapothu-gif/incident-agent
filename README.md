# Autonomous Incident Triage Agent

An incident-response assistant that investigates service health, searches remediation runbooks with Gemini embeddings and Supabase pgvector, and pauses for human approval before escalating a ticket.

## Features

- LangGraph workflow with persistent Postgres checkpoints
- Gemini-powered incident triage and tool calling
- Service health checks for auth, database, and payments
- Semantic search over internal remediation runbooks
- Human-in-the-loop approval before sensitive escalation actions
- FastAPI endpoints and a Gradio web interface

## Requirements

- Python 3.10+
- A Google Gemini API key
- A Supabase Postgres database with the `vector` extension enabled

## Setup

1. Create and activate a virtual environment:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

2. Install dependencies:

   ```powershell
   pip install -r requirements.txt
   ```

3. Create a `.env` file in the project root:

   ```dotenv
   GEMINI_API_KEY=your_gemini_api_key
   DATABASE_URL=postgresql://user:password@host:5432/database
   ```

   Keep `.env` private. It is excluded by `.gitignore`.

## Database Setup

Run this SQL in the Supabase SQL editor before seeding the runbooks:

```sql
create extension if not exists vector;

create table if not exists incident_docs (
    id bigint generated by default as identity primary key,
    content text not null,
    metadata jsonb not null default '{}'::jsonb,
    embedding vector(768) not null
);
```

Then generate embeddings and insert the included runbooks:

```powershell
python seed_rag.py
```

The seed script currently adds runbooks for auth, database, and payment services.

## Run the Application

Start the combined FastAPI and Gradio application:

```powershell
python app.py
```

Open [http://localhost:7860](http://localhost:7860) in a browser.

The deployed application is available at [https://incident-agent-tibn.onrender.com](https://incident-agent-tibn.onrender.com/).

To use another port, set `PORT` before starting the app:

```powershell
$env:PORT = "8000"
python app.py
```

## API

### `POST /chat`

Start or continue an incident thread:

```json
{
  "thread_id": "incident-001",
  "message": "Auth service is timing out. Investigate and escalate if needed."
}
```

The response is either `COMPLETED` or `AWAITING_APPROVAL`. When approval is required, the response includes the pending action and its parameters.

### `POST /approve`

Approve or reject a pending sensitive action:

```json
{
  "thread_id": "incident-001",
  "approved": true
}
```

To reject an action, set `approved` to `false` and optionally provide `rejection_reason`.

## Workflow

1. The agent receives an incident description.
2. It checks the health of relevant services.
3. It searches the runbook vector store for remediation guidance.
4. If escalation is needed, execution pauses before the sensitive tool.
5. An engineer approves or rejects the escalation.
6. The workflow resumes and persists state by `thread_id`.

## Project Files

- `agent.py` - LangGraph workflow, tools, Gemini models, and Postgres checkpointing
- `app.py` - FastAPI routes and Gradio interface
- `seed_rag.py` - Embedding generation and runbook seeding
- `requirements.txt` - Python dependencies
- `.env` - Local credentials and configuration; do not commit it

## Security Notes

- Rotate any API keys or database passwords that have been exposed.
- Never commit `.env` or place credentials in source code.
- Protect the `/approve` endpoint with authentication and authorization before deploying publicly.
- Review generated escalation parameters before approving sensitive actions.
